# Linux 生产级网络状态探测与套接字审计手记

本文档记录了网络工程师视角下的 Linux 底层网络状态探测规范、核心排错命令机理解析与生产安全审计标准。

---

## 一、 现代网络工具链标准规范 (iproute2)

全面废除过时的 `net-tools`（淘汰 `ifconfig`、`route -n`、`netstat`），统一采用内核原生支持的 `iproute2` 体系：

| 传统过时命令 | 现代工业界标准命令 | 核心优势 |
| :--- | :--- | :--- |
| `ifconfig -a` | `ip -br a` | 单行精简输出（Brief），清晰呈现网卡名、UP/DOWN 状态与 CIDR IP |
| `route -n` | `ip route` | 直接读取内核转发表（FIB），毫秒级呈现下一跳与出接口 |
| `netstat -tulnp` | `ss -tulnp` | 直接通过内核 `netlink` 接口读取套接字信息，海量连接时不卡死 |

---

## 二、 路由转发表 (`ip route`) 深度解析

典型输出条目：
```text
default via 192.168.128.2 dev ens33 proto dhcp metric 100
192.168.128.0/24 dev ens33 proto kernel scope link src 192.168.128.128 metric 100
```
- **默认路由 (`default via ...`)**：未匹配到任何明细路由时的出口网关。
- **网关 `.2` 的底层原理**：VMware NAT 虚拟交换机中，宿主机 Windows 虚拟网卡固定占用 `.1`，虚拟 NAT 路由网关分配在 **`.2`**。

## 三、 套接字深度排错 (`ss`) 核心规则

### 1. POSIX 参数自由合并规则
单字母开关选项（Switch Flags）顺序无关且可任意拼合：
`ss -tulnp` 等价于 `ss -t -u -l -n -p` 或 `ss -lntup`。

### 2. 核心参数场景化对照

| 参数 | 英文全称 | 核心作用 | 典型实战场景 |
| :---: | :--- | :--- | :--- |
| `-t` | TCP | 仅筛选 TCP 传输层协议 | 排查 Web（80/443）、数据库、SSH 服务 |
| `-u` | UDP | 仅筛选 UDP 传输层协议 | 排查 DNS（53）、WireGuard 隧道（51820） |
| `-l` | Listening | 仅查看处于监听状态的服务端口 | 检查服务是否已成功启动并守候端口 |
| `-n` | Numeric | 强制以纯数字显示 IP 和端口 | **生产排查必备！彻底规避 DNS 逆向解析导致的终端假死** |
| `-p` | Process | 显示占用端口的进程名与 PID | 定位冲突进程或非法占用（需 `sudo` 提权完全显示） |

## 四、 监听地址安全分级与审计场景

### 1. 地址绑定与攻击面 (Attack Surface)
- **`0.0.0.0` / `[::]`（通配绑定）**：监听本机所有物理和虚拟网卡。外部公网可达，必须依赖防火墙（UFW/nftables）与强认证机制。
- **`127.0.0.1` / `127.0.0.0/8`（环回绑定）**：严格锁死在本机回环网卡（`lo`）。外部数据包无法在内核中路由到该接口，安全级别极高。

### 2. 生产高频自测与排错实战
- **场景 1：排查外部正在发起的 CC/DDoS 攻击连接**
  - **命令**：`ss -tan`
  - **原理**：去除 `-l`（不看监听），增加 `-a`（查看全部活跃连接），通过 `Peer Address` 直接捕获外部攻击源 IP 及连接状态（`ESTAB`、`SYN-RECV`）。
- **场景 2：内部中间件（如 Redis/Memcached）防未授权暴露**
  - **错误配置**：`bind 0.0.0.0`（导致云上未授权访问漏洞，可被黑客注入 Webshell）。
  - **合规配置**：`bind 127.0.0.1`（仅允许本机 Web 服务调用，阻断外部直接扫描与渗透）。
